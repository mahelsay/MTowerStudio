# MTower Studio — Azure decision log

Each decision records what was chosen, the options considered, and why. The user decided each one on 2026-10-12 unless noted. Research sources (Microsoft Learn, Azure Retail Prices API, fetched 2026-10-12) are listed at the end.

| ID | Decision | Options considered | Why |
|---|---|---|---|
| D-01 | **Managed models in Azure Foundry; LoRA work stays on fal.ai** (hybrid studio) | Self-hosted GPU VMs; OpenAI API direct; fal only | Foundry gives gpt-image, FLUX and Sora pay-per-use with no servers to run. Azure has no managed LoRA training or LoRA inpainting, and GPU VMs (A100/H100) would cost about $2.5–3k/month. |
| D-02 | **Personal external tenant, not the Microsoft work subscription** | Work subscription ($3k/month); external tenant ($700/month) | MTower is a personal project on a personal GitHub account; a company subscription is for company work. $700/month is ample for pay-per-use. |
| D-03 | **Region East US 2 (`eastus2`), everything in one region** | East US (the first choice); split East US + East US 2; Sweden Central | East US has **no** gpt-image or Sora 2 deployment. East US 2 is the one US region that hosts all gpt-image models, sora-2, FLUX Kontext/FLUX.2 and Speech. |
| D-04 | **One SPN, Contributor on the subscription**, used for deploys and by the engine | Two identities (deployer + engine-only); no SPN (interactive sign-in) | User preference for simplicity. Trade-off documented in [security.md](security.md). Roles are granted separately by the Owner. |
| D-05 | **Everything as code (Bicep), built now** | Wait for the tenant move; build by hand in the portal | The subscription moves tenant in about 2 weeks. With code, the move is one re-run plus re-granting roles. |
| D-06 | **Naming:** `me-<region>-mtower-studio-<type>`, lowercase; region code `eus2`; deployments `me-eus2-<model>` | Capitals (`Mtower-Studio`); no type ending; deployments named after the model only | Lowercase is required by some resources. Type endings make the portal and the bill readable. User chose `eus2` and the prefixed deployment names. Full rules: [naming.md](naming.md). |
| D-07 | **IP allow-list + Entra-only sign-in; no private endpoints** | Private endpoints + P2S VPN (VpnGw1AZ, about $157/month); private endpoints now and VPN later (about $25/month) | A private endpoint can't be reached from a home PC without a VPN gateway. The allow-list gives "only my PC" for $0, and keys are disabled. See [security.md](security.md) for the upgrade path. |
| D-08 | **Models:** gpt-image-2, gpt-image-2.5-flare, FLUX.1-Kontext-pro, FLUX.2-pro, sora-2 (all Global Standard) | Minimal (two models); images only | Idle deployments cost nothing. gpt-image-2/2.5 are generally available (no access application); gpt-image-1/1.5 still need one. Sora 2 is deployed only to test realism, since Microsoft documents that it blocks photorealistic content. |
| D-09 | **Media backup in Azure Storage** `meeus2mtowerstudiost` | Local only (+ Google Drive) | Protects approved media against disk loss; about $1–3/month for 50–100 GB. |
| D-10 | **Logs to the user's existing Log Analytics workspace** | New workspace `me-eus2-mtower-studio-log` | User preference. |
| D-11 | **Budget $300/month**, alerts at 50/80/100% actual and 100% forecast, to maelsayed@microsoft.com | $500; $700 | A full episode of keyframes should cost well under $300. The engine's monthly limit for Azure is set to match. |
| D-12 | **Budget start date fixed at 2026-10-01** | `utcNow()` on each deploy | A budget's start date can't be moved later; a fixed date keeps re-deploys safe. |
| D-13 | **Network Security Perimeter** `me-eus2-mtower-studio-nsp` (Enforced) around Foundry and storage; one inbound rule for the studio PC's IP | Policy exemption; private endpoints + VPN | Found at deploy time: the tenant policy **SFI-NS2.2.1 Secure PaaS Resources – Storage accounts** (Modify, assignment *MCAPSGov Deploy and Modify Policies*, root management group) forces storage public access to Disabled unless the resource is in an NSP. NSP is free, generally available for Storage and Foundry, complies with the policy, and is stricter (deny by default; perimeter rules take precedence over each resource's own setting). Names approved by the user. |
| D-14 | **Child shots on FLUX.1-Kontext-pro** (`safety_tolerance` 5), with the child's approved casting photo as the input image; no new deployment | ChatGPT by hand; deploy FLUX.2-flex or FLUX-1.1-pro; fal | Tested 2026-10-12 with the same child prompt: gpt-image-2 and gpt-image-2.5-flare are blocked by output moderation, FLUX.2-pro answers HTTP 200 with `stop_reason: refusal` (and may still bill a few cents). Kontext-pro renders it, keeps the casting face, and costs $0.04. Added by the director after the user allowed any model deployment. |
| D-15 | **Face pass on Azure: gpt-image-2 masked edit with the actor's anchor portrait** (engine `face_swap`, default); fal LoRA inpainting stays for children only | fal LoRA inpaint (old default); FLUX.2-pro multi-reference edit; gpt-image `--actor-refs` at composition time | A/B on 2.5-07 (2026-10-13): the fal inpaint enlarged the captain's head, turned it to the camera and lit it warm; FLUX.2-pro changed the whole picture and lost the likeness; the gpt-image masked edit (tight ellipse mask, `input_fidelity` high) kept head size, angle and moonlight and matched the actor, for $0.043. Decided by the director after the user asked to move image work to Azure. |
| D-16 | **Vision QA reviewer `me-eus2-gpt-5-6-sol`** (gpt-5.6-sol 2026-07-09, Global Standard, 100K TPM) checks every image against its design (`mtower qa`, `mtower autofix`) | gpt-5.6-terra (half the price); gpt-5.5; no automatic review | The user asked for a generate → check pipeline. The newest flagship vision model gives the most reliable judgement of anatomy, identity and period detail; about $0.05–0.09 per image. A structured "measure the people first" step was needed before it caught oversized or warm-lit faces. Added by the director under the user's standing permission to deploy models. |
| D-17 | **Narration takes on Azure Speech** (part of the Foundry resource; `ar-AE-Rashid` HD, `ar-EG-Shakir`, `ar-SA-Hamed`) for the Look Test and the animatic | ElevenLabs only; gpt-4o-mini-tts | No deployment needed, a few cents per beat. ElevenLabs remains the planned final narrator. |
| D-18 | **gpt-image calls send `moderation: low`** (compositions and face swaps) | Default `auto`; apply for Azure's modified content filtering | gpt-image's own output moderation rejected face swaps on ordinary battle shots (3.4-05, 5.4-05). `low` is the documented OpenAI image-API setting for less restrictive filtering; Azure accepted it and the rejected 3.4-05 swap went through (2026-10-13). Azure's own content filters still apply, and gpt-image still refuses every photorealistic child even with `low` (retested 2026-10-13), so child shots stay on FLUX Kontext (D-14). |
| D-19 | **Series narration in everyday Egyptian Arabic** (user, 2026-10-13): `narration_egyptian.md` read by default, voices `ar-EG-Shakir` (lead) / `ar-EG-Salma`; the screenplay's formal VO stays the source of truth for meaning; every take is checked with Azure speech-to-text (`voice --check`) | Formal Arabic narration (the screenplay VO); Egyptian for dialogue only | The user wants it closer to the audience. Azure's Egyptian voices are good enough for drafts; ElevenLabs (better dialect) remains the planned final narrator once its key is set. |
| D-20 | **Drama-first direction** (user, 2026-10-13): characters carry the scenes with short Egyptian dialogue and reactions; narration cut to about a third and told in the first person by Hamdi Shalabi remembering, decades later; proven first by a small Dialogue Test. **Acted voices on Azure:** deployed `me-eus2-gpt-4o-mini-tts` (gpt-4o-mini-tts 2025-12-15) and `me-eus2-gpt-audio-1-5` (gpt-audio-1.5 2026-02-23), both Global Standard, capacity 10 | Pure drama without a narrator; documentary style; ElevenLabs for voices | The user asked to stay on Azure. Both models take acting directions in plain words (e.g. "whispering into a radio, steely calm"); the Azure Speech catalogue has no expressive Egyptian voice (ar-EG Shakir/Salma have no styles; MAI-Voice-2.1 has no Arabic yet; DragonHD Omni voices list ar-EG as a secondary language). A 4-engine bake-off (`audio/voice_test/20261013-150514`) decides the voices by ear. Lip-synced video still needs fal (Veo 3.1 / Kling): Sora 2 on Azure refuses photorealistic people (D-08). |
| D-21 | **Performance system** (user, 2026-10-13: "voices and intensity must match the intense, action or drama situation"): one fixed voice per character in `production_config.json` → `voice_cast` (approved voice or approved audition); every `dialogue_refs` line carries intensity 1–10, volume, pace, emotion, delivery (and fx); the engine builds the situation from the screenplay and directs gpt-audio-1.5 with it (`mtower dialogue`, `audition`, `lipsync`, `animatic --dialogue`); takes are re-recorded until speech-to-text hears the words, and loudness-matched to their volume. Narration is now `narration_hamdi.md` (old Hamdi, first person, 22 of 42 beats, ≈30% of the words) voiced by cast N-01. Lip-sync default: Kling AI Avatar v2 Pro on fal (user pick from the Dialogue Test). Guide: `productions/thunderbolt/ep01_romani/03_production/voice/performance_guide.md` | Per-scene ad-hoc scripts (the Dialogue Test tools); intensity judged by the gpt-audio listener; ElevenLabs | The first Shalabi take was too relaxed because nothing told the voice what was happening. A written performance per line makes every take reproducible and reviewable; the AI listener proved too generous to judge acting, so it checks only the words and the user judges the acting by ear. |
